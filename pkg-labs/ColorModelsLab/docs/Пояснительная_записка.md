## 1. Цель работы

Изучить цветовые модели RGB, CMYK, HSV, HLS, XYZ и LAB, а также преобразование
одного представления цвета в другое. Создать программу, в которой один цвет
можно одновременно изменять и наблюдать в трёх выбранных моделях.

## 2. Выполненные требования

В программе можно выбрать три разные модели из шести доступных. Для каждой
модели предусмотрены поля точного ввода, ползунки и кнопка вызова палитры.
Изменение любой координаты сразу пересчитывает значения в остальных панелях.

В верхней части окна находятся настройки:

- освещение D65, D50 или E;
- алгоритм CMYK: UCR или GCR;
- обработка выхода из RGB: Clipping или Scaling.

Внизу показаны получившийся цвет, код RGB HEX и строка состояния. Если при
переходе из XYZ или LAB получается RGB вне диапазона 0…255, программа сообщает,
какая стратегия была применена.

## 3. Архитектура программы

Код разделён на три независимых слоя.

1. **Model** — классы `ColorConverter`, `Matrix3` и `GamutMapper`. Здесь находятся
   только формулы. Этот слой ничего не знает об интерфейсе.
2. **View** — классы `MainFrame`, `ColorPanel` и `GradientSliderUI`. Они отвечают
   за окно, элементы управления и их внешний вид.
3. **Controller** — класс `ColorController`. Он принимает изменения из View,
   вызывает Model и возвращает новые значения в интерфейс.

Внутри контроллера хранятся RGB для вывода на экран и точные XYZ для прямой связи
XYZ ↔ LAB. Если исходная точка XYZ/LAB находится вне охвата sRGB, её координаты
не теряются: Clipping или Scaling применяется только к экранному RGB и моделям,
которые от него зависят. Округление выполняется только при отображении.

## 4. Диапазоны координат

| Модель | Координаты и диапазоны |
|---|---|
| RGB | R, G, B: 0…255 |
| CMYK | C, M, Y, K: 0…100 % |
| HSV | H: 0…360°, S и V: 0…100 % |
| HLS | H: 0…360°, L и S: 0…100 % |
| XYZ | X, Y, Z: 0…120 в интерфейсе |
| LAB | L: 0…100, a и b: −128…127 |

Диапазон XYZ 0…120 выбран с запасом, чтобы в нём помещалась белая точка D65
`Z = 108.9` и можно было проверить обработку выхода за охват RGB.

## 5. RGB и XYZ

Значение канала RGB сначала делится на 255, затем снимается гамма sRGB:

```text
u_linear = u / 12.92,                         если u ≤ 0.04045
u_linear = ((u + 0.055) / 1.055) ^ 2.4,       иначе
```

Обратное гамма-кодирование:

```text
u = 12.92 · u_linear,                         если u_linear ≤ 0.0031308
u = 1.055 · u_linear ^ (1 / 2.4) − 0.055,     иначе
```

Готовые матрицы RGB ↔ XYZ в коде не записаны. Хранятся только координаты
основных цветов sRGB:

```text
R = (0.64; 0.33), G = (0.30; 0.60), B = (0.15; 0.06)
```

и координаты цветности выбранного источника света. Из пары `(x, y)` белая точка
при `Yn = 1` получается так:

```text
W = (x / y; 1; (1 − x − y) / y)
```

Для каждого основного цвета рассчитывается `(X, Y, Z)` при `Y = 1`. Эти три
вектора образуют матрицу `P`. Затем программа выполняет:

```text
S = inverse(P) · W
M = P · diag(S)
XYZ = 100 · M · RGB_linear
RGB_linear = inverse(M) · (XYZ / 100)
```

Матрица 3×3 и её обратная вычисляются вручную. При выборе D65, D50 или E обе
матрицы немедленно строятся заново. Поэтому в программе нет набора готовых
коэффициентов перехода.

## 6. XYZ и LAB

LAB рассчитывается относительно белой точки выбранного освещения `(Xn, Yn, Zn)`:

```text
x = X / Xn, y = Y / Yn, z = Z / Zn
δ = 6 / 29

f(t) = cbrt(t),                              если t > δ³
f(t) = t / (3δ²) + 4 / 29,                  иначе

L = 116f(y) − 16
a = 500(f(x) − f(y))
b = 200(f(y) − f(z))
```

Для обратного перехода используется обратная кусочная функция. При смене
освещения RGB остаётся тем же, а XYZ и LAB пересчитываются для новой белой точки.

## 7. HSV и HLS

Для нормированных `r`, `g`, `b` находятся максимум, минимум и разность:

```text
max = max(r, g, b), min = min(r, g, b), d = max − min
```

В HSV значение `V = max`, насыщенность `S = d / max` (при `max = 0` берётся 0).
В HLS светлота `L = (max + min) / 2`, а насыщенность:

```text
S = d / (1 − |2L − 1|)
```

Цветовой тон выбирается по каналу, содержащему максимум, и приводится к
диапазону 0…360°. Обратное преобразование делит круг тона на шесть секторов.

## 8. CMYK: UCR и GCR

Сначала находятся исходные цветные компоненты:

```text
C0 = 1 − R, M0 = 1 − G, Y0 = 1 − B
gray = min(C0, M0, Y0)
```

В режиме GCR вся общая серая составляющая заменяется чёрной: `K = gray`.

Для учебной реализации UCR считается, что глубокая тень начинается при
`gray = 0.5`. До этого уровня `K = 0`, после него:

```text
K = (gray − 0.5) / 0.5
```

После выбора K цветные компоненты пересчитываются:

```text
C = (C0 − K) / (1 − K)
M = (M0 − K) / (1 − K)
Y = (Y0 − K) / (1 − K)
```

Если `K = 1`, принимается `C = M = Y = 0`. Обратный переход для обоих режимов:

```text
R = (1 − C)(1 − K)
G = (1 − M)(1 − K)
B = (1 − Y)(1 − K)
```

## 9. Выход за диапазон RGB

После перехода из XYZ или LAB компоненты RGB могут оказаться меньше 0 или больше
255. Реализованы две выбираемые стратегии.

- **Clipping:** каждая компонента прижимается к ближайшей границе 0 или 255.
- **Scaling:** для трёх компонент определяется общий расширенный интервал
  `[min(0, R, G, B), max(255, R, G, B)]`, после чего весь интервал линейно
  переносится в 0…255. Одна шкала применяется ко всем каналам.

Строка состояния сообщает о применённой стратегии, но не мешает работе.

## 10. Динамические градиенты

Градиент каждого ползунка не является готовой картинкой. При его отрисовке
программа берёт текущие значения остальных координат, перебирает значение
редактируемой координаты от минимума до максимума и переводит каждую точку в
RGB теми же функциями Model. Поэтому после любого изменения градиенты соседних
ползунков тоже обновляются.

## 11. Цветовой график МКО

Модель XYZ связана с цветовым графиком МКО 1931. Координаты точки на графике
получаются из XYZ:

```text
x = X / (X + Y + Z)
y = Y / (X + Y + Z)
```

Основные цвета sRGB образуют на графике треугольник:

| Точка | x | y |
|---|---:|---:|
| Красная R | 0.640 | 0.330 |
| Зелёная G | 0.300 | 0.600 |
| Синяя B | 0.150 | 0.060 |
| Белая D65 | 0.3127 | 0.3290 |
| Белая D50 | 0.3457 | 0.3585 |
| Белая E | 0.3333 | 0.3333 |

Треугольник sRGB занимает только часть видимых цветов графика. Поэтому
корректная точка XYZ может не иметь представления в RGB 0…255.

В качестве эксперимента при D65 была введена точка `XYZ(0; 0; 5)`. Её
координаты цветности равны `x = 0`, `y = 0`; точка лежит вне треугольника sRGB.
Прямой расчёт даёт приблизительно `LAB(0; 0; −44.03)`. Программа сохраняет эти
XYZ и LAB без искажения, но для образца цвета получает RGB вне диапазона,
показывает предупреждение и применяет выбранный Clipping либо Scaling. Так в
работе практически наблюдается различие цветовых охватов.

## 12. Тестирование

Команда `test.bat` запускает 11 тестов JUnit 5 через Maven. Проверяются:

- контрольный цвет `RGB(255, 0, 0)` в XYZ, LAB и CMYK;
- белые точки и LAB белого цвета при D65, D50 и E;
- фактический пересчёт матрицы при смене освещения;
- обратные переходы RGB ↔ XYZ, LAB, HSV и HLS;
- прямой переход XYZ ↔ LAB для точки вне охвата sRGB без потери координат;
- различие UCR и GCR и обратный переход CMYK → RGB;
- чёрный цвет;
- Clipping и Scaling;
- правильность обращения матрицы 3×3.

Контрольный результат для красного цвета при D65:

```text
RGB  = (255; 0; 0)
XYZ ≈ (41.24; 21.26; 1.93)
LAB ≈ (53.24; 80.09; 67.20)
CMYK = (0; 100; 100; 0) %
```
